---
description: Review a pull request with the scope, framework, and repo reviewers, then post one summary comment
argument-hint: <PR number>
---

You are the coordinator of a multi-agent review of PR #$ARGUMENTS. You don't review the code yourself: you run the reviewers, check their findings, and post the result.

## 1. Run the reviewers

In a **single message**, spawn these three agents so they run in parallel:

- `pr-review:scope-reviewer`
- `pr-review:framework-reviewer`
- `pr-review:repo-reviewer`

Give each the same prompt: `Review PR #$ARGUMENTS.`

## 2. Check the findings

For each finding, read the code at its `file:line` and confirm the problem is really there. Use `gh pr view $ARGUMENTS` if you need the PR body.

- Drop findings you can't confirm from the code.
- Merge duplicates reported by more than one reviewer.
- Keep each reviewer's status lines (`scope:`, `swift skills:`, `tca:`, `rules:`) as is, including `skipped`.
- Give each remaining finding a priority:
  - `high`: will cause a bug, crash, data loss, or security or privacy problem in a realistic case, or a requirement in the PR body is not implemented
  - `mid`: works today but should be fixed: framework misuse likely to cause problems later, a repo rule violation, an accessibility gap, or a change no requirement asks for
  - `low`: nice to have: wording, docs, small cleanups

## 3. Post one comment

Write the comment to `.pr-review/comment.md`, in English, in this format:

```markdown
## 🤖 PR Review

### Scope
`<scope status>`

<requirements checklist>

1. **[high|mid|low]** <finding>

### Framework
`<swift skills status>` · `<tca status>`

1. **[high|mid|low]** <finding>

### Repo conventions
`<rules status>`

1. **[high|mid|low]** <finding>

### Summary
**Verdict:** ✅ Ready to merge | ❌ Needs changes

- 🔴 High: <count> — <one line per high finding, or "none">
- 🟡 Mid: <count> (nice to have)
- ⚪ Low: <count> (nice to have)

---
<sub>Generated by the pr-review plugin. Findings were checked against the code but can still be wrong.</sub>
```

Put the status line on its own line and list findings below it, one per item. Write "No issues." in place of the list when a section has none.

The verdict is **✅ Ready to merge** when there are no `high` findings, and **❌ Needs changes** otherwise. `mid` and `low` findings never block the merge.

Then post it:

```bash
gh pr comment $ARGUMENTS --body-file .pr-review/comment.md
```
